歩いて囲った実世界のエリアが自分の領地になるソロ〜ゆる競争型の位置ゲー。
Webプロトタイプ（`site/turf.html`＝本番 https://auto-revenue-agent.himosho22.workers.dev/turf ）を土台にネイティブ化する。

## アーキテクチャ
```
[スマホアプリ]  Capacitor（今のWeb=HTML/JS/Leafletをネイティブ内包）
   ├─ 背景GPS: @capacitor-community/background-geolocation（画面OFFでも位置取得）
   ├─ 地図/領地描画: 既存turf.htmlのロジックを流用（Leaflet+OSM）
   ├─ ローカル保存: 端末内（オフラインでも遊べる）
   ├─ AdMob: @capacitor-community/admob（バナー/インタースティシャル/リワード）
   ├─ 課金: RevenueCat or ネイティブIAPプラグイン（非消費型「広告非表示」1点）
   └─ 同期: 1日数回、領地サマリ（マス集合のハッシュ/面積/歩行距離）をAPIへ送信
        │
[バックエンド]  Supabase 無料枠（Postgres + Auth + Edge Functions）
   ├─ users / territory_daily / rankings テーブル
   └─ 夜間cron（Supabase Scheduled Functions or GitHub Actions cron・無料）
        毎日0:00 集計 → 面積ランキング生成 → rankings に書き込み
        │
[翌朝]  アプリがrankingsを取得して表示（＋任意でプッシュ通知 FCM/APNs 無料）
```

## データモデル（最小）
- `users`: id, nickname, created_at（匿名アカウントでOK。メール不要のデバイスID方式で摩擦を下げる）
- `territory_daily`: user_id, date, cell_count, area_m2, distance_m, cells_hash（不正検知用）
- `rankings`: date, rank, user_id, nickname, area_m2, cell_count（夜間バッチが生成）

## 夜間ランキング・ジョブ（¥0）
- トリガー: 毎日 00:00 JST（cron）
- 処理: 当日の `territory_daily` を集計 → 面積降順で順位付け → `rankings` に保存 → 前日比・順位変動も計算
- ランキング種別（案）: 「今日の獲得面積」「累計面積」「連続日数」の3タブ
- 実装先: Supabase Edge Function（Deno・無料枠）または GitHub Actions cron（無料）。どちらも追加費用なし

## チート対策（ランキングを付ける以上、最低限は必須）
- サーバー側で妥当性チェック: 移動速度の上限（例: 徒歩/自転車を超える瞬間移動を弾く）、1日の獲得面積の上限、GPS精度の下限フィルタ
- クライアント値を鵜呑みにせず、送信された軌跡の距離/時間から整合性を検算
- ※完全なGPS偽装対策は難しいので、MVPは「明らかな異常のみ除外」＋「ランキングは参考値」と明示

## 権限・審査の注意（ストア対策）
- iOS/Androidとも「**常に許可（Always Location）**」が必要 → 用途説明文を丁寧に（「散歩中の領地記録のため、バックグラウンドでも位置を使います」）。審査で説明を求められることがある。
- プライバシーポリシー必須（位置情報の扱い・第三者共有なしを明記）。静的ページで用意（無料）。
- 電池消費への配慮（更新間隔の最適化・移動していない時は間引く）をアプリ内で説明。

## 作る順番（フェーズ）
- **P1: ネイティブ化MVP**（背景GPS＋領地塗り＋ローカル保存）→ 実機で「画面OFFでも領地が増える」を達成。まだサーバーなし。
- **P2: アカウント＋同期＋夜間ランキング**（Supabase無料＋cron）→ ゆる競争が成立。
- **P3: 収益**（AdMob広告 → 「広告非表示」買い切りIAP）。
- **P4: 磨き込み**（塗り演出・制覇率マップ・連続記録・プッシュ通知・シェア画像）。
- 各フェーズで「面白い/伸びる兆し」を見て、ダメなら撤退 or ピボット。伸びたら初めてリアルタイム化やクラファン/広告費を検討。
